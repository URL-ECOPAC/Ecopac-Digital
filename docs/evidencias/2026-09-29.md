## Incidencias del entorno, que no son defectos del sistema

1. **Sin acceso a la API de GitHub desde este entorno.** No hay `gh` instalado ni un
   `GITHUB_TOKEN` disponible, asi que no se pudo citar el numero de una corrida del CI para
   "Regresion" ni confirmar el estado de los checks requeridos en GitHub directamente. Se
   ejecutaron los mismos comandos que corre el CI (lint, tests, build, pgTAP, e2e) de forma local
   en su lugar, todos en verde. Queda pendiente que alguien con acceso a GitHub confirme la
   corrida real del PR o del push a `develop`.
2. **Stack local desactualizado al empezar.** El contenedor de Supabase local llevaba varios dias
   arriba, de antes de las migraciones 00134 a 00156. Se corrigio con
   `supabase db reset` antes de correr pgTAP, e2e y la prueba de carga: los tres corrieron contra
   el esquema actual, no contra uno viejo.
3. **`supabase` no resolvia en el PATH de este entorno.** Mismo riesgo ya documentado en el plan.
   Se resolvio con un shim en `~/.local/bin/supabase` que llama a
   `npx --yes supabase@2.115.0`, sin tocar nada del repositorio.
